🎤 SAO Control · La Chalupa

Control de servicios musicales para LA CHALUPA LERMA · Contexto v2.0 · Actualizado el 18 de Septiembre de 2026

📋 ¿Qué es?

Una PWA single-file de uso personal para que Javi SAO lleve el control de los servicios musicales que brinda en el restaurante LA CHALUPA LERMA (responsable: Jesus Arias Velazco). Registra servicios con horas reales, pagos con método (efectivo/transferencia/depósito), préstamos y compras, y calcula el saldo pendiente acumulado global. Genera reportes para el cliente: copiables a WhatsApp 📲 y PDF estilo Estado de Cuenta cronológico con saldo corrido 📊.

🧠 Regla de oro: los pagos cubren primero los cargos más viejos (calcularEstados() con servicios+extras unificados). Saldo global = Servicios + Extras − Pagos.

🧠 Modelo de Datos

Todo vive en DATA_APP, guardado en localStorage con clave 'saoChalupaData':

ArrayEstructura de cada item
servicios[]{ id, fecha, tipo, horaInicio, horaFin, horas, costo }
pagos[]{ id, fecha, monto, nota, metodo } 💳
extras[]{ id, fecha, tipo, concepto, monto } 💸🛒

💡 El saldo NO se guarda: se calcula en vivo. Migración automática en cargarDatos(): si faltan extras o metodo en datos viejos, se crean vacíos. Clave extra: 'saoUltimoRespaldo' (fecha del último respaldo).

📦 Sistema de Respaldo

  • ⬇️ Exportar: descarga respaldo-sao-chalupa-YYYY-MM-DD.json con TODO (Blob + a[download]) y registra la fecha en 'saoUltimoRespaldo'
  • ⬆️ Importar: input file oculto → FileReader → valida formato → muestra caja de confirmación con conteos → ✅ RESTAURAR reemplaza DATA_APP (con migraciones) o ❌ Cancelar
  • 🏠 La tarjeta del HOME muestra "Último respaldo: fecha" o "⚠️ Todavía no hiciste ningún respaldo"

📲 PWA - Detalles

  • sw.js: estrategia NETWORK-FIRST 🌐 (con internet muestra SIEMPRE lo último; sin internet usa caché). ⚠️ Diferencia con Maggie (cache-first).
  • CACHE_NAME: 'sao-chalupa-v2'
  • Íconos: pack de favicon.io (texto SAO, fondo #8e24aa)
  • og:image con URL ABSOLUTA al android-chrome-512x512.png (WhatsApp no lee SVG)
  • Las actualizaciones de código llegan solas al abrir con internet (no reinstalar)

💡 Lecciones Aprendidas / Tips

  • 🔑 localStorage es local y FRÁGIL: el cel puede borrarlo solo (pasó el 18/Sep). Por eso existe el Respaldo 📦: exportar seguido.
  • 🔑 Un pago con fecha FUTURA se resta del saldo global pero NO aparece en reportes por periodo → descuadre invisible. Guardia 🛡️ + comparar HOME vs reporte.
  • 🔑 Inputs type="time": usar oninput Y onchange para actualización en vivo en todos los navegadores.
  • 🔑 Al reemplazar bloques HTML: revisar colitas huérfanas (<p> sueltos, > de más, inputs duplicados).
  • 🔑 Fechas ISO YYYY-MM-DD se comparan como texto; objeto Date a mediodía evita el bug del día anterior.
  • 🔑 Copiar en móvil: textarea + execCommand. Toasts en vez de alert().
  • 🔑 favicon.io = pack completo de íconos en un click. og:image necesita PNG + URL absoluta.
  • 🔑 Network-first durante desarrollo = cero dolor de versiones viejas.
  • 🔑 GitHub Pages tarda 1-3 min por commit. WhatsApp cachea previews: usar ?v=2.

🕵️ Crónicas de Guerra (casos resueltos)

CASO 1 · El Borrado

18/Sep/2026: la app abrió sin ningún dato (el navegador limpió localStorage). Los datos se reingresaron a mano. Nació el sistema de Respaldo 📦 para que nunca más duela.


CASO 2 · El Pago Fantasma

18/Sep/2026: el reporte marcaba saldo $1,230 pero sus líneas sumaban $2,230. Diagnóstico: HOME "Pagos" $9,100 vs reporte $8,100 → pago de $1,000 con fecha Domingo 27/Sep (futuro, sin nota) excluido del periodo pero contado en el global. Solución: borrado con doble toque. Saldo real restaurado: $2,230. Nació el guardia 🛡️ de fechas futuras.
